# Rime 功能全表与合并取舍

以仓库实际启用的组件为准，覆盖虎码·常用、虎码·全字集、小鹤双拼、全拼。文件存在不等于已开启，真实机器需自行 apply、重新部署。

## 已合并的公共工具

| 功能 | 入口与处理 |
| --- | --- |
| Emoji | 两边共用合并映射，雾凇优先、虎码补充、精确去重；统一开关名 `emoji`，首次按启动方案设置默认值，切方案不重置。 |
| 日期时间 | 共用 `date_translator` 与 `date_commands`：`/d` 日期，`/t` 时间，`/dt` 日期时间，`/ts` 时间戳，`/dw` 星期，`/dm` 英文月份；分号日期入口已移除，英文关键词可模糊搜索。 |

| 数字金额大小写 | 同一个 `number_translator`；虎码 `S123.45`，雾凇 `R123.45`，输出相同转换候选。 |
| 计算器 | 同一个 `calc_translator`；虎码 `=1+2`，雾凇 `cC1+2`；结果和算式两种候选，未完成算式显示解析失败。虎码原通用 Lua 表达式语法不再支持。 |

| 按需加载 | 方案使用 `@*module`；不再在 `rime.lua` 全局预加载未启用的排序、日历、提醒等模块，移除硬编码 Homebrew Lua 5.4 搜索路径。 |

## 与虎码上游的空码差异

上游采用四码长度限制和 `auto_clear: max_length`，没有本地的 `fixed4segmentor` 连打分段，也没有 `echo_translator` 字面兜底。原生自动清码以无候选菜单为条件；本地为空码保留字面候选以避免候选框闪烁，因此不能直接照搬。上游的“空格清空空码”键位仅为注释样例，并未启用；相同关键配置的小词典隔离测试确认，空码后直接按空格仍可提交原始编码，继续输入下一个编码才会触发清空。

本地只保留一项针对连打的提交例外：`quick_input` 调用 `tiger.commit_guard`，在空格或逗号、句号提交前检查各分段的已选候选，仅丢弃 `raw` 字面分段，保留有效分段及其简码记录。正常候选直接交给原生组件；不用占位符，也不再用正则从提交文本中删除字母。

## 尚未开启的可选功能

| 功能 | 工作量 | 输入体验与取舍 |
| --- | --- | --- |
| UUID | 小 | 需要标识符时再接入。 |
| 候选置顶 | 小 | 可固定姓名或常用词，但需要具体编码和词，不能自动套样例。 |
| 英文补全＋自动大小写 | 中 | 需词典、拼写和排序适配，会增加中英文重码。 |
| 中英混合词库 | 中 | 与纯英文补全不同，需要为小鹤 / 全拼选择各自词表。 |
| 英文候选降权 | 小，依赖英文混输 | 不开英文就不需要。 |
| 中文英文间自动空格 | 小，改变提交文本 | 对代码、路径、格式敏感场景不一定合适。 |
| 41,448 拼音大字表 | 小 | 候选和部署成本增加；已有虎码全字集时必要性较低。 |
| 别名、翻译、化学式 | 小 | 来自 `others.txt`，会增加非 Emoji 候选。 |
| 模糊音 | 中 | 需明确 n/l、平翘舌、前后鼻音等需求，不能全拼双拼直接套同一规则。 |
| 多条整句候选 | 小 | 原生 `max_sentences`，需相应版本且可能增加计算量。 |
| 语法模型 | 大 | 额外模型、内存和更新链路，长句效果需实测，不保证改善。 |
| 其他双拼 / T9 | 中 | 增加方案、词表和快捷键，当前只用小鹤时不需要。 |
| 单字优先 / 长词优先 / 仅单字 | 中 | 旧 Lua 模块已删除；需要时再选择一套策略接入。 |
| 用户词典标记、调试器、Vim 联动 | 实验性 | 对应未启用实验模块已删除。 |
| 手机键盘有刻 / 无刻 / 助记 | 前端相关 | 虎码有选项名，但本仓库桌面配置没有对应手机键盘实现。 |

原则：公共工具留一个实现，方案保留各自编码与手感；原生 Rime 组件不因出现在两套方案里就算两份代码。只有实际启用的组件进入相应方案的处理链。

## 模块清理与保留

已删除 11 个未启用模块，并将目标路径加入 `.chezmoiremove`，供以后 apply 时清理旧部署文件：

- 旧字集与单字过滤：`executable_core2022_filter.lua`、`executable_dz_ci_filter.lua`。
- 候选排序：`candidate_sorting/` 下的 `executable_single_char_only.lua`、`executable_single_char_first.lua`、`executable_long_phrase_first.lua`、`long_word_filter.lua`。
- Vim 实验联动：`nvim/im_select.lua`、`nvim/vimmode.lua`。
- 其他辅助：`cn_en_spacer.lua`、`debugger.lua`、`is_in_user_dict.lua`。

保留以下两个运行模块，其中 `search` 已默认启用：

| 文件（相对于 `lua/`） | 用途与限制 |
| --- | --- |
| `pin_cand_filter.lua` | 对指定编码的已有候选按固定顺序置顶，例如让“他、她、它”始终按设定顺序出现。不会生成词条；新增短语仍用 `custom_phrase.txt`。匹配的是变换后的候选拼音显示，小鹤当前显示全拼，因此规则需要按全拼填写。 |
| `executable_search.lua` | 拼音输入后追加辅码，按汉字部件或其他反查编码筛选已有候选，减少同音字翻页。需要配置辅码来源；当前方案使用 `radical_pinyin` 部件拼音，现已接入全拼、小鹤部件词典和独立拼写索引，默认启用。 |

`lib/librime.lua` 是 Lua 类型注解，供编辑器补全使用，不是待启用的运行组件，保留。方案中提到的 UUID、英文自动大小写等可选上游模块，不一定有对应本地文件。

## 同步与换行

- 本地维护、不会自动同步的文件统一使用 LF，包括 `tiger.schema.yaml.tmpl`、`tiger.custom.yaml`、`symbols.yaml` 和 `lua/executable_unicode_display.lua`，不按最初来源区分。
- 原样读取的虎码全字典、雾凇主字典，以及链接到上游的词库、基础部件方案和 OpenCC，保留上游换行，不增加转换流程。
- 已有解析生成流程的虎码常用字典、简码表和合并 Emoji 产物使用 LF；常用字典解析时同时规范化 CRLF，不另起转换进程。

## 当前已知待处理项与验证边界

- 简码推荐表已改为从常用字典生成：仅一码、两码首选字，同字取最短编码，与常用字典共享上游指纹和缓存，不依赖目标文件写入顺序。
- Emoji 开关名已统一为 `emoji`，简转繁开关名统一为 `traditionalization`，对应滤镜与快捷键同步修改。普通开关已移除 `reset`，在当前会话内保留；`save_options: []` 不跨重启保存。简码提醒与记录仍在新会话默认开启，Emoji 初始值由启动方案决定。下划线开头的手机键盘选项仍按方案初始化。
- 旧 `nvim/mathmode` 已移除，四方案共用 `quick_input`；`jj`、`tt` 仅小鹤直出，分号前后两个方向分别用于功能 / 原样直出和符号。松开、Ctrl/Alt/Super、ASCII 模式、特殊键和光标在输入中间时均不触发。
- 简码事件逐条追加文件，尚无压缩或通知冷却；不是每次按键写入。多个前端进程同时运行时，各自内存汇总不会实时同步。
- 隔离测试覆盖四方案部署与主要输入路径；未 apply 到真实配置，未验证真实桌面通知、macOS 前端和手机性能。
